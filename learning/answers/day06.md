## 1. 错误的种类

“编译错误”“运行时异常”“逻辑错误”有什么区别？每类给一个独立于比较整数、闰年题的简短例子，可以用文字。

我的回答：编译错误是无法通过编译生成可执行文件，运行时异常是运行时出现导致程序无法继续运行的错误，逻辑错误是不干扰运行，但是无法解释的情况。
3/0是编译错误，手动输入除数时，输入了0，导致出现3/0的运算是运行时异常，if(3<0){输出3>0}是逻辑错误

什么是变量的作用域？为什么在一个大括号代码块内声明的局部变量，通常不能在代码块外直接使用？作用域限制有什么好处？

即一个变量可以被引用的区域。因为局部变量不可做为全局变量使用。好处是为了让有限的字母表达更多的意思。

### 第 1 题：错误分类需纠正

- 编译错误是违反 Java 语法或类型等编译规则，例如 `int count = "三";` 类型不匹配。常规 javac 编译生成的是 .class 字节码，不是通常所说的本机可执行文件。
- `3 / 0` 不能直接归为编译错误。助手用 JDK 17 实测完整语句 `System.out.println(3 / 0);`：javac 编译成功，执行时抛出 ArithmeticException。键盘输入整数除数 0 也会产生同类运行时异常。IDE 可能提前提示风险，但提示不等于 javac 一定拒绝编译。这里说的是普通表达式语句，不泛化到必须使用编译期常量的特殊上下文。
- 运行时异常发生在程序执行期间；如果未处理，会中断相应执行流程，但异常可以被处理，不必然使整个应用停止。异常处理后续会学习。
- 逻辑错误是行为或结果与需求不符，不是“无法解释”。例如需求是求长方形面积却写成长 + 宽：程序可以正常运行，但公式不符合需求。
- 你的 `if (3 < 0) { 输出 3 > 0 }` 条件恒为 false，分支不会执行；仅凭这个片段、没有期望行为，不能证明它必然是逻辑错误。

整数除零规则可核对 [Java 17 语言规范 §15.17.2](https://docs.oracle.com/javase/specs/jls/se17/html/jls-15.html#jls-15.17.2)。

### 第 2 题：定义正确，原因与好处需要补充

“变量可以被引用的区域”是正确方向，更准确地说是变量名在源码中可被使用的范围。Java 规定块内声明的局部变量，其作用域受该块限制；外部代码不能直接引用这个名字。不是因为它被写入磁盘，也不是变量值不能改变。

限制作用域有助于减少命名冲突、避免不相关代码误用临时变量，让代码依赖更清晰。在不同且不重叠的作用域中复用名称是结果之一，主要目的不是节约字母。
