## 1. 五个常用算术运算符

| 运算符 | 用途 | 示例结果 |
|---|---|---|
| + | 加法（也可拼接字符串） | 8 + 3 得到 11 |
| - | 减法 | 8 - 3 得到 5 |
| * | 乘法 | 8 * 3 得到 24 |
| / | 除法 | 8 / 3 得到 2；8 / 3.0 约为 2.666667 |
| % | 取余 | 8 % 3 得到 2 |

`%` 在这里不是百分号，也不是 printf 里的格式占位符。它计算除法的余数。

比如 23 支笔，每盒装 5 支：

```java
int pens = 23;
int capacity = 5;
int fullBoxes = pens / capacity;
int remainingPens = pens % capacity;
```

结果是 4 个完整盒子，剩 3 支。可用下面的关系检查：

```text
原数量 = 商 × 每组数量 + 余数
23 = 4 × 5 + 3
```

本课只处理非负整数，除数严格大于 0。此时余数一定大于等于 0、小于除数。整数除以 0 或对 0 取余会出错；输入验证等学 if 时再处理，不要把 0 用作本课除数。

## 2. 运算优先级

先算括号，再算 `* / %`，最后算 `+ -`；同一组里的运算按从左向右分组：

```java
int a = 2 + 3 * 4;
int b = (2 + 3) * 4;
int c = 20 / 3 * 3;
```

请先预测，再用示例验证。第三行先做整数除法，截掉的小数不会因为后续乘法恢复。

连接 Day02：你的 `c * 9 / 5` 中，c 是 double，先乘再除能正确保留小数。如果写成 `c * (9 / 5)`，括号里的整数除法会先得到 1。括号会改变分组方式，不是加得越多越正确。

字符串拼接也要注意顺序：

```java
System.out.println("合计：" + 2 + 3);
System.out.println("合计：" + (2 + 3));
```

第一行从左向右进行字符串拼接，第二行先完成括号内的加法。

## 4. 练习 A：把秒数拆成时、分、秒

编辑 `Day03Practice.java`。声明一个 int 总秒数，默认值为 3661，计算并输出小时、分钟、秒。

要求：

- 不能把结果写死；修改总秒数后，重新运行能得到正确结果。
- 小时表示总时长中的完整小时数，可以超过 23；不是一天内的钟表时刻。
- 分钟和秒必须在 0～59 之间。
- 暂时不需要输入、判断或循环，逐次修改变量并运行即可。

| 总秒数 | 预期小时 | 预期分钟 | 预期秒 |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 59 | 0 | 0 | 59 |
| 60 | 0 | 1 | 0 |
| 3661 | 1 | 1 | 1 |
| 86399 | 23 | 59 | 59 |
| 86400 | 24 | 0 | 0 |

提示：先取出完整小时，再从剩余秒数中取出完整分钟，最后得到剩余秒数。也可以先算总分钟数，再考虑怎样让“分钟部分”不超过 59。自己选择一种思路。

自查：小时 × 3600 + 分钟 × 60 + 秒，应恰好还原总秒数。全部验证后恢复默认 3661。

## 7. Git 小练习：提交后又修改了文件

本次核验发现：Day02 提交已在 GitHub，但你随后勾选日志中的复选框，这些新修改还没进入提交。HEAD 与远端相同，并不代表工作区没有新改动。

从仓库根目录执行以下查看命令：

```powershell
Set-Location 'D:\code\Java\Daily-Java'
git status --short
git diff -- learning/logs/day02.md
```

补全日志、完成今日练习后，可按下面步骤上传；如遇到以前的目录信任问题，参考 Day02 Git 教程：

```powershell
git add -- learning
git diff --cached --stat
git diff --cached
git commit -m "study: complete Day03 exercises and follow up reviews"
git push origin main
git status --short
```

最后一个 status 应显示仍未提交的内容；如果只剩根目录那个以 tudy 开头的 diff 文件，说明课程改动已提交，而该文件仍未跟踪。网页还需确认新提交已出现。若只提交了讲义与空模板，把提交说明改为 `docs: prepare Day03 and record Day02 review`。

根目录的 tudy 文件没有提交到远端，内容像误保存的旧 diff。助手没有删除它；确认不需要后可自行整理。使用 `git add -- learning` 限定范围，可以避免把它顺带上传；仍需检查课程文件夹内的全部暂存差异。
