## 每日工作流

1. 保存亲手编写的代码、实际日期、用时、收获和疑问。
2. 告诉助手：“请审阅 DayXX，修改后将今天的学习记录上传到学习仓库。”
3. 助手先检查实际差异，运行适当验证，并给出批改。
4. 学习者修改后，更新日志和进度；确有未解决的问题时也可提交，但标明“待修正”。
5. 只提交本课程相关文件，使用真实学习日期；不补造历史、不伪造完成状态。
6. 确认远端提交成功后，把提交链接记录在当天日志里。

建议保留“初次尝试”和“批改修正”两个真实提交，便于回看思路；如果某天只有一份最终提交也完全可以。提交次数不是学习成果的衡量标准。

## 文件范围

提交讲义、源代码、必要的构建配置、日志和项目说明。忽略编译产物、IDE 个人状态、密钥、环境变量文件和本地数据库数据。后续数据库配置通过环境变量传入，示例只保留占位值。

当前采用本机 Git 的 HTTPS 远端。提交前检查暂存差异，推送后核对远端 SHA；如需要认证，使用 Git Credential Manager 或浏览器登录，不要把访问令牌发到聊天中。
